# ARKAON 승인형 하이브리드 GPU 운영 구조

## 운영 원칙
- **로컬 PC**: 관리자 승인 후에만 작업 수행. 기본 비활성. 최초 목적은 진입 영상 1회 제작.
- **유료 GPU**: 상용화 이후 선택적으로 사용. 작업별 예산 상한·관리자 승인·만료 시간 필수. 비용 초과 시 작업 중단.
- **공통**: 작업 요청 → 서버에서 사용자 인증 및 관리자 권한 확인 → 작업·공급자·예산·만료시각 승인 → 대기열 → 해당 공급자 작업자가 일회성 실행 허가 확인 → 결과 검증 → 다운로드/배포 승인.
- 공급자 변경(로컬↔임대)은 기존 승인 재사용 금지. 새 승인 필요.
- 로컬 PC에 공개 인바운드 포트를 열지 않고, 인증된 작업자만 서버 대기열을 **아웃바운드 폴링**.
- 유료 GPU 임대 API 키는 서버의 비밀 저장소에만 보관. 브라우저, Netlify 정적 파일, GitHub 저장소에 넣지 않음.
- 작업마다 생성물 소유권·로그·원가·소요시간·모델 버전·승인자·결과 해시 기록. 고객별 격리, 재시도 멱등성, 정산 정책은 운영 단계에 구현.

## 현재 구현 범위
`engine/hybrid_gpu/policy.py`는 외부 서비스에 연결되지 않은 **순수 정책 코어**이며, 승인 전 작업 실행을 거부하고 공급자 고정, 예산 한도, 만료, 중복 디스패치 방지 로직을 담는다.
`engine/hybrid_gpu/test_policy.py`에 단위 테스트가 있다.

**아직 미구현**: 실제 서버 인증/관리자 권한, 영속 DB 트랜잭션, 분산 작업 대기열, 토큰 원자적 소비, 로컬 워커 설치, GPU 공급자 어댑터, 과금·결제, 실제 영상 모델, 배포 검증. 따라서 이 코드를 운영 승인 보안 장치로 단독 사용하면 안 된다.
