## 후보 1 — 읽기 전용 도메인 검증 분리
- 문제: 화면·저장·외부 API가 뒤섞이면 잘못된 데이터가 운영 상태에 반영될 위험.
- 재사용 가능 원리: 순수 함수로 타입·범위·불변식 검증 후 별도 저장 계층에 전달.
- 입증 범위: 재고 수량 예약/해제, 등록 사전검사 및 Python 테스트가 작성됨.
- 미입증: 실제 DB 트랜잭션, 인증, 운영 환경 성능.
- 검토 시험: 음수·부울·소수·예약 초과·동시성·경계값 테스트.
- 판정: 후보 유지. 운영 적용 불가.

## 후보 2 — 안전한 사전검사와 한국어 오류
- 문제: 잘못된 상품 코드, 가격, 수량을 사용자에게 명확히 설명해야 함.
- 원리: 입력 정규화 → 유효성 검사 → 필드별 안정적인 오류 코드 → 사용자 언어 메시지.
- 입증 범위: SKU 공백 정규화, 중복 검사, 숫자 검증, 한국어 시연 화면.
- 미입증: 실제 등록 경쟁 조건. DB에서 tenant 범위 고유 제약 필요.
- 검토 시험: 오류 코드 계약, 국제화, 유니코드·길이 경계, 동시 등록.
- 판정: 후보 유지. 운영 적용 불가.

## 후보 3 — 비영속 시연 샌드박스
- 문제: 실제 결제·재고·사용자 데이터를 건드리지 않고 기능을 체험시키기.
- 원리: 가상 데이터와 브라우저 메모리만 사용; 서버 요청·스토리지·운영 권한 분리.
- 입증 범위: 독립형 시연 화면, 임시 상품 메모리 표시, 새로고침 초기화 의도.
- 미입증: 실제 브라우저 E2E와 접근성 자동 검증.
- 검토 시험: 새로고침, 필터, 오류 시 초기화, DOM 안전성, 키보드 조작.
- 판정: 후보 유지. 운영 적용 불가.

## 후보 4 — 변경 감사 및 릴리스 게이트
- 문제: 자동 개발 과정에서 비인가 경로 변경과 검증 누락 방지.
- 원리: intent_DNA 범위 제한, 보호 경로, 패치·감사 증빙, CI와 사람 승인 분리.
- 입증 범위: 정책·검증 스크립트와 Draft PR에 구현됨.
- 미입증: GitHub Actions 실행은 GitHub 결제 장애로 막힘. CI 통과 주장 금지.
- 검토 시험: 우회 경로, 보호 파일 변경, 감사 무결성, CI 재실행.
- 판정: 후보 유지. 운영 적용 불가.
