# 10. v0.1 API·DB·화면·테스트 명세

- 명세 ID: APF-PRODUCT-001

## 서비스 경계

Identity/Governance, Target Catalog, Evidence, Ingestion, Intent, Analysis Orchestrator, Pattern, Validation, Review/Approval, Registry/Search, Audit/Metrics.

## API

- POST /v1/targets
- POST /v1/targets/{id}/authorizations
- POST /v1/targets/{id}/snapshots
- POST /v1/snapshots/{id}/artifacts
- POST /v1/analysis-runs
- POST /v1/analysis-runs/{id}/intent-dna
- POST /v1/analysis-runs/{id}/execute
- POST /v1/analysis-runs/{id}/hold
- GET /v1/analysis-runs/{id}
- POST /v1/pattern-candidates
- POST /v1/pattern-candidates/{id}/validations
- POST /v1/pattern-candidates/{id}/reviews
- POST /v1/pattern-candidates/{id}/approvals
- POST /v1/pattern-candidates/{id}/publish
- GET /v1/pattern-packages
- GET /v1/pattern-packages/{namespace}/{slug}/{version}
- POST /v1/pattern-search
- POST /v1/reuse-cases
- POST /v1/reuse-cases/{id}/evidence

모든 mutation은 Idempotency-Key, If-Match revision, actor context를 요구한다. publish는 approval token과 expected content_hash가 필요하다.

## 핵심 테이블

tenants, principals, role_assignments, analysis_targets, target_authorizations, source_evidence, target_snapshots, source_artifacts, intent_dna, intent_hypotheses, analysis_budgets, analysis_runs, observations, inferences, domain_maps, analysis_gaps, pattern_candidates, pattern_versions, applicability_rules, pattern_relations, module_candidates, validation_runs, findings, reviews, review_decisions, approvals, pattern_packages, package_releases, search_documents, reuse_cases, reuse_evidence, audit_events, outbox_events.

공통 컬럼: id UUIDv7, tenant_id, created_at, created_by. 변경 aggregate는 revision. append-only 테이블은 update/delete 금지. 외래키와 상태별 partial unique index로 중복 active run과 중복 official version을 막는다.

## 화면

1. Foundry Dashboard: 목표·품질·HOLD·오염 현황
2. Target Registry: 권한·등급·Snapshot
3. Intent Workbench: DNA 축·가설·근거·예산
4. Analysis Workspace: 사실/추론/누락 3분할
5. Pattern Studio: 추상화·인터페이스·불변조건·테스트
6. Validation Center: 보안·출처·오염·충돌
7. Approval Queue: diff, evidence, risk, 독립승인
8. Pattern Registry: 버전·관계·폐기·검색
9. Reuse Composer: 신규사업 Intent와 Package 조합
10. Audit Explorer: actor·event·correlation 추적

## 테스트 층

- Unit: DNA fingerprint, gate, transition, semver, score
- Contract: AFP envelope, API schema, Package schema
- Integration: DB constraint, outbox, object store, search ACL
- Security: IDOR, tenant escape, prompt injection, secret leakage
- Concurrency: 중복 실행·승인·출시 경쟁
- Golden: 동일 Snapshot의 결정적 구조 산출
- Contamination: 고객명·문구·코드 유사도
- E2E: 등록→DNA→분석→후보→승인→검색→재사용
- Metrics: 3개 플랫폼, 5유형, 30패턴, 10모듈, 50% 단축, 혼입 0

## 비기능

API p95 read 500ms, mutation 1s(비동기 분석 제외). 검색 p95 1.5s. Audit 유실 0. RPO 15분, RTO 4시간. 공식 Package와 승인로그는 일관된 백업과 복원검증을 갖는다.
