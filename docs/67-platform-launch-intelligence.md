# ARKAON Platform Launch Intelligence v1

아르카온이 공개된 공식 제품 자료에서 플랫폼 개설 흐름의 일반 원리만 학습하고,
독립 구현한 자산으로 이미지 대화 시스템에 연결하는 계층이다. 모델 가중치를 자율 변경하는
학습이 아니라, 출처와 시험이 남는 검토 가능한 패턴 자산을 축적한다.

## 조사 경계

- Wix, Webflow, Framer, Bubble의 공식 공개 제품 페이지만 사용한다.
- 단계에 대한 짧은 사실 요약과 출처 URL만 보관한다.
- 타사의 코드, 화면 디자인, 문구, 비공개 동작은 복제하지 않는다.
- 서로 다른 두 업체 이상에서 확인된 일반 기능은 공통 패턴으로 승격할 수 있다.
- 단일 업체 사례도 아이디어·기능 원리의 활용이 허용되는 범위라면 예외 심사를 거칠 수 있다.
  권리 검토 `PASS`, 사용자 scope 승인 digest, clean-room 독립 구현, 서로 다른 두 범주의
  독창적 보완, 비유사성 검토 `PASS`가 모두 있어야 한다. 하나라도 없으면 기본 보류한다.
- 예외 승인은 해당 기능 원리에만 적용한다. 원 개발자의 코드, 문구, 이미지, 화면 구성,
  상표·특허 등 보호 대상의 사용 허가로 확대 해석하지 않는다.

출처 원장은 `knowledge/platform-launch/official-flow-observations-v1.json`에 있다.

## 독립 개설 흐름

1. 사용자가 목적을 한 문장으로 말한다.
2. 구조나 위험 통제를 바꾸는 질문만 추가한다.
3. 이미지 형태의 시작안들을 제시한다.
4. 사용자가 대화로 수정하고 직접 미리 본다.
5. 목적, 이용자, 화면 흐름, 데이터·권한, 비용·결제를 쉬운 말로 확인한다.
6. 명세 승인, sandbox 구현 승인, 운영반영 승인을 서로 분리한다.

개인정보, 역할 권한, 결제가 없으면 관련 상세 질문은 나타나지 않는다. 해당 기능이 있으면
필요한 질문과 통제가 조건부로 추가된다. 결제는 별도 승인 전까지 sandbox로만 다룬다.

## 코드 연결

`platform_launch_intelligence.build_blueprint`는 최소 질문의 완료 여부를 판정하고 PR #52의
`PlatformBrief`를 생성한다. 출력에는 출처 묶음의 SHA-256 digest가 포함되며 구현과 배포
권한은 항상 `false`이다. 이후 시각 대화가 화면안을 만들고 사용자의 이해 확인을 받는다.

## 자산 승격 조건

현재 자산 상태는 `INDEPENDENT_IMPLEMENTATION`이다. 아르카온 시험과 에테르니언 독립 감사,
사용자 승인이 모두 끝나기 전에는 `OWNED_ASSET`으로 승격하지 않는다. 특히 가장 빠르다는
주장은 실제 사용성 시험에서 완료 시간, 중도 이탈, 되묻기 횟수를 비교한 뒤에만 확정한다.

단일 사례 예외는 ‘모방을 통한 새로운 창조’라는 개발 방향을 수용하되, 표현의 복제가 아니라
검증된 아이디어를 우리 목적에 맞게 다시 설계하는 통제 경로다. 법적 불확실성이 있거나 권리
검토가 `PASS`가 아니면 `HOLD`하고 별도 확인을 받는다.

차별화 범주는 고유 색상·시각 체계, 서체 체계, 텍스트·상호작용 애니메이션, 이용 흐름,
접근성 동작, 업종 특화 기능으로 관리한다. 색상이나 애니메이션도 자산 후보가 되지만 외형만
조금 바꾼 결과는 승인하지 않는다. 최소 두 범주를 결합하고 그중 하나는 이용 흐름·접근성·
업종 기능처럼 사용자 가치가 달라지는 기능적 차별화여야 한다.

## 아르카온 기능적 차별화 판정 가이드

세부 판정표와 제출 양식은
`knowledge/platform-launch/distinctive-asset-guidelines-v1.json`을 단일 기준으로 사용한다.

| 범주 | 인정되는 변화 | 인정되지 않는 변화 | 반드시 남길 증거 |
|---|---|---|---|
| 이용 흐름 | 순서, 분기, 오류 복구 또는 피드백 방식이 달라짐 | 버튼 위치·이름만 변경 | 전후 단계, 달라진 판단점, 완료·오류 측정 |
| 접근성 | 키보드, 상태 텍스트, 동작 축소, 비색상 단서로 같은 목표 완료 | 색을 진하게 하거나 hover 설명만 추가 | 키보드 완주, 초점, 대체 표현, 동작 축소 시험 |
| 업종 기능 | 업종 고유 역할·상태·규칙·증빙을 데이터와 통제로 구현 | 일반 기능의 명칭·아이콘만 업종화 | 행위자·상태·실패·롤백 및 업종 시나리오 |

예를 들어 부업장터의 `의뢰 → 지원 → 배정 → 수행 → 검수 → 정산` 상태와 역할 권한 연결은
업종 기능으로 인정한다. PG의 원거래에 결속된 승인·취소·환불·정산보류, 건설 인력 배정 전
자격·안전교육 확인도 인정한다. 반면 일반 게시판을 ‘건설 게시판’으로 이름만 바꾸거나 동일한
화면의 색상만 바꾸는 것은 인정하지 않는다.

텍스트 애니메이션은 목적, 시간 범위, 동작 줄이기 동작, 정지 상태의 동일 정보 전달을 모두
명시해야 한다. 색상은 명명된 디자인 토큰, 대비 검증, 색 외의 상태 단서를 함께 제공한다.

## 아르카온 최소 승인 작업지시

에테르니언은 단일 사례 기반 자산마다 다음과 같이 지시한다.

> 아래 결과물을 모두 제출하기 전에는 사용자 승인 요청을 생성하지 않는다. 참고할 일반 원리와
> 공식 출처를 기록하고, 원본 코드·문구·레이아웃·이미지·브랜드 자산은 사용하지 않는다고
> 구체적으로 표시하라. 우리 사용자의 불편을 정의한 뒤 색상·서체·모션 중 한 범주와 이용
> 흐름·접근성·업종 기능 중 한 범주를 골라 각 범주에서 최소 두 항목을 독립 구현하라.
> 전후 화면과 이용 단계를 나란히 제시하고 기능·접근성·비유사성·회귀 시험을 수행하라.
> 산출물 SHA-256, 남은 위험, 롤백 방법과 정확한 승인 scope digest를 결과 manifest에 넣어라.

색상을 선택하면 디자인 토큰, 대비 결과, 색 이외의 상태 표시까지 제출해야 한다. 애니메이션을
선택하면 목적, 지속시간, 반복조건, 동작 줄이기 설정, 정지 대체안을 제출해야 한다. 기능은
정상·실패·되돌리기 시나리오와 합격 기준이 필요하다. 하나라도 빠지면 `HOLD`한다. 전부
갖춰도 자동 승인하지 않고, 쉬운 말과 전후 이미지로 인석형에게 최종 판단을 요청한다.
