# 65. 일반어·시각 승인과 플랫폼 대화 확장

## 목적

자기개선 요청은 일반 사용자가 문제, 변경점, 이익, 위험, 영향, 롤백을 충분히 이해한
뒤 승인해야 한다. 기술 원문을 그대로 노출하거나 단순한 확인 버튼으로 동의를 받지 않는다.

## 승인 화면

- 문제·변경·효과·영향·위험·롤백을 쉬운 말로 표시한다.
- 변경 전과 변경 후를 단계형 시각 자료로 함께 표시한다.
- 기술 범위와 일반어 설명은 같은 `scope_digest`에 결속한다.
- 에테르니언 의미검토의 `plain_digest`와 review digest가 유효한 보고서만 표시한다.
- 승인·보류·거절 모두 인증된 owner, CSRF, 일회 nonce, 만료시각과 함께 기록한다.
- 결정 receipt는 exclusive-create와 fsync로 저장하며 자동 병합·배포 권한을 주지 않는다.

## 플랫폼 생성 대화로의 확장

후속 `ARKAON Visual Platform Dialogue v1`은 같은 결속 방식을 다음 반복 과정에 적용한다.

1. 사용자가 만들 플랫폼의 목적과 이용자를 설명한다.
2. 아르카온이 화면 구조와 이용 흐름을 이미지로 제시한다.
3. 사용자가 이미지의 특정 화면·요소를 선택해 수정 의견을 남긴다.
4. 아르카온이 새 이미지와 변경 설명을 재출한다.
5. 매 회차의 이미지 digest, 요구사항 digest, 변경 이유를 이력으로 남긴다.
6. 사용자가 기능·화면·권한·비용·데이터 이용을 각각 이해 확인한다.
7. 최종 확인된 이미지와 구조만 플랫폼 명세로 봉인한다.

이미지는 설명 보조 수단이며 텍스트 명세를 대체하지 않는다. 이미지와 명세가 다르면
`HOLD`하고, 최종 명세 digest가 달라지면 이전 승인은 무효화한다.
