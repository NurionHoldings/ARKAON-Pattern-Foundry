# 목적 선택·결제·구현 단계 흐름 v1

사용자가 목적상품과 정확한 구현 범위를 승인한 뒤 sandbox 결제창을 열고, 신뢰된 결제
어댑터가 결제 완료를 검증해야 아르카온 구현을 시작한다. 결제는 승인된 scope를 확대하지
않으며 최종 상태는 운영반영 승인 대기다.

## 단계

1. 목적상품·가격·통화·허용 경로·scope digest·사용자 승인 digest 확정
2. 해당 확정본에 결속된 결제창 생성
3. 신뢰된 결제 어댑터가 금액·통화·결제창·환경을 검증
4. 결제 완료 receipt 저장 후 `IMPLEMENTATION_READY`
5. 동일 scope digest로만 `SANDBOX_IMPLEMENTING` 시작
6. 아르카온 구현·1차 검증
7. 에테르니언 독립 감사·필요 시 보완
8. 결과 보고
9. `DEPLOYMENT_APPROVAL_PENDING`에서 정지

## 결제 안전 경계

현재 구현은 `SANDBOX` 이벤트만 받으며 실제 PG·카드·계좌를 호출하지 않는다. 결제창에는
선택본 digest, 금액, 통화, scope digest를 결속한다. 금액·통화 불일치, 오래된 결제창,
미검증 이벤트, 중복 ID의 다른 내용은 차단한다. 동일 webhook 재전송은 같은 결과를 반환한다.

결제 실패·취소는 재시도 가능한 새 결제창으로만 이어진다. 성공 후 환불·취소가 확인되면
기존 증거를 삭제하지 않고 `HOLD_PAYMENT_REVERSED`로 전환해 이후 구현을 멈춘다.

## 역할과 승인

- 결제 완료는 승인된 구현의 시작조건이지 범위·병합·배포 승인이 아니다.
- 아르카온만 구현과 1차 검증을 수행한다.
- 에테르니언만 독립 감사·승인 범위 내 보완·최종 검증을 기록한다.
- 모든 단계 전환에는 별도 SHA-256 증거가 필요하다.
- 자동 병합과 운영 배포는 항상 `false`다.
