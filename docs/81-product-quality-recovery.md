# 유료 제품 품질 회복: 화면·내용·학습 연결

## 실제 원인

main의 services/site-builder.html은 제목/소개/연락처를 단일 div로 출력했다.
co_creation_codegen._render_section_stub는 주석만 있는 빈 section을 출력한다.
이 상태에서 수집량이나 평가기 수가 늘어도 사용자 결과물이 풍부해지지 않는다.

## 이번 수직 범위: 홈페이지 제작 화면

기존 홈페이지 만들기 URL에서 목적 → 분위기 → 내용의 세 단계로 전환한다.
세 업종의 서로 다른 대표항목·설명 가이드·절차·FAQ를 제공한다.
대표항목에 `이름 | 설명`을 입력하면 실제 설명이 렌더링되며, 비어 있으면 가이드임을
표시한다. 차별점·고객·소개·연락 안내도 결과물에 반영한다.
editorial/night/minimal은 색뿐 아니라 hero 배치, 카드 구조, 여백이 달라진다.
모바일 미리보기와 누락 항목 목록, 이 브라우저 초안 저장을 제공한다.
임의의 후기·경력·가격을 만들지 않으며 연락/예약/결제 연결을 가장하지 않는다.
다운로드·출력·공개 게시를 추가하지 않는다. 기존 금융/인증 코드는 변경하지 않는다.

## 공개 참고자료와 차별화

- https://support.wix.com/en/article/wix-editor-creating-an-ai-generated-site
  목적/사업 brief에서 시작하고 같은 brief로 theme/layout을 수정하는 흐름.
- https://www.framer.com/academy/lessons/build-your-first-site
  페이지·내용·breakpoint를 함께 보고 preview에서 흐름을 검사하는 방식.

2026-10-24 공개 문서의 이용 흐름만 관찰했다. 소스·문구·이미지·브랜드 표현을 복사하지
않았다. 독자 한국어 편집기, 세 업종 내용팩 및 모바일 비교를 직접 구현했다.
타사보다 우수하다고 검증되거나 공식 학습 자산으로 승격된 것은 아니다.

## 더 나은 디자인을 학습해 코드로 반영하기 위한 다음 필수 연결

1. 업종/사용 목적별 공개 관찰 후보에 URL·관찰시점·허용범위·채택할 원리를 기록한다.
2. 같은 사용자 brief로 기존/후보 디자인을 렌더링한다. 코드 정적 점수만으로 선택하지 않는다.
3. 360/390/768/1440px에서 넘침·대비·키보드 이동·링크를 검사하고 이미지 증거를 저장한다.
4. 실제 사용자에게 첫 미리보기까지 단계 수, 도움 요청, 수정 성공과 선호를 비교한다.
   학습 후보 채택에는 이 비교 증거 및 권리/접근성 검토를 결속한다.
5. 채택 원리를 코드/내용팩 변경으로 연결하고 고정 평가 brief에서 퇴보를 검사한다.
   통과 결과만 사용자 승인 후 버전 자산으로 활성화한다. 자동 운영 승격은 하지 않는다.

## 남은 범위와 한계

이 화면은 규칙 기반 초안이며 LLM 글쓰기·자료 인식·이미지 생성·자율 웹 학습은 없다.
고객별 풍부한 카피 생성, 미디어 업로드, 세부 페이지, 운영 worker 교훈 연결,
co-creation 빈 stub 교체 및 유료 entitlement 통합은 아직 구현하지 않았다.
서비스 목록·메인 홈 전체가 재설계된 것으로 표시하지 않는다.
브라우저 실제 시각/접근성 검증 및 사용성 비교 전 디자인 개선 효과를 확정하지 않는다.
롤백은 이 PR revert이며 저장된 기존 작업은 변경하지 않는다.
