# ARKAON — 실운영 전환 실행 기준

## 목적
기존에 기획된 모든 기능을 한꺼번에 공개하지 않고, 검증된 기능부터 단계적으로 출시한다. 이 문서는 **출시 승인 문서가 아니다**. 운영 준비 증거를 모으는 기준이다.

## 단계
1. **현황 감사**: 현재 main, 배포된 Netlify 산출물, API/DB/인증/결제/권한/개인정보 기능을 대조한다. 코드 존재와 실동작을 구분한다.
2. **공통 운영 기반**: 사용자 인증, 서버 비밀관리, DB 영속성, 백업·복구, 로그·알림, 오류 처리, 운영자 권한, CI 및 배포/롤백.
3. **독립 진입 화면**: 영상 자산, 모바일/저사양 대체 화면, 접근성, 성능, 실제 브라우저 E2E 확인. 기능 연결은 후속 단계.
4. **영상 제작실**: 자체 GPU 워커와 오픈소스 모델 실측, 요청 큐, 과금 상한(초기 월 5만~10만 원), 작업 중지 및 GPU 자동 종료. 유료 GPU 임대는 별도 명시 승인 후 실행.
5. **서비스 기능**: 회원가입/로그인, 미리보기, 저작권 동의, 결제·청구서·영수증, 권한별 다운로드, 사용자 저장소 선택, 템플릿 제작, 검색엔진 등록, AI 공동작업.
6. **외부 연동**: GitHub/Netlify 등 최소권한 OAuth/서버 측 토큰. 사용자별 자격증명 격리 및 폐기.
7. **출시**: 개별 기능에 대한 보안·결제·법적 고지·데이터보전·모바일·접근성·실사용 E2E 증빙, 운영자 승인 후 제한 공개 → 일반 공개.

## 차단 기준
- `ops/production-readiness.json`의 `production_public_enabled` 기본값은 false.
- 실제 증빙 URL, 확인 시각, 통과 판정이 없으면 readiness 스크립트는 실패한다.
- 스크립트가 통과해도 외부 서비스·실결제·GPU 비용을 자동으로 활성화하지 않는다.
- 이 체크는 **선언형 검증**이다. 실제 보안 감사, 브라우저 테스트, 결제 검증을 대체하지 않는다.
- Netlify 배포는 현재 GitHub 커밋만으로 확인되지 않으며 별도의 실제 배포 및 URL 검증이 필요하다.
- 기존 운영 사이트/메인 브랜치는 검증·승인 전 변경하지 않는다.
