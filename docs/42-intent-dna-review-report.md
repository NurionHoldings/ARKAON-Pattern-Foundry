# Intent_DNA 기반 에테르니언 승인 보고 규격

## 목적

에테르니언 우편함의 승인 대상을 건별로 반복 설명하지 않고, 변하지 않는 사용자 의도와
공통 원인을 기준으로 군집화하여 분석·판단·개선에 드는 시간과 수고를 줄인다.

이 규격은 보고 효율을 높일 뿐 승인 경계를 완화하지 않는다. 계약, 결제, 지급,
개인정보 공유, 분쟁 합의, 운영 변경, 배포, 병합 및 공식 패턴 승격은 별도의 명시 승인을
계속 요구한다.

## 필수 처리 순서

READ → EXTRACT_INTENT_DNA → CLUSTER → ANALYZE → IDENTIFY_CAUSE → PROPOSE_IMPROVEMENT
→ ESTIMATE_SAVINGS → AUTHORIZE → EXECUTE → VERIFY → REPORT

실행 성공과 검증 성공은 분리한다. 증거가 부족하거나 Intent_DNA 신뢰도가 낮으면
승인하지 않고 HOLD 또는 BLOCKED로 보고한다.

## 보고서 필수 필드

1. **Intent_DNA**
   - 목표, 반드시 지킬 제약, 금지사항, 성공조건, 허용된 권한, 신뢰도
2. **분석**
   - 대상 건수, 동일 의도·동일 원인 군집, 대표 증거, 영향 범위
3. **원인**
   - 직접 원인, 구조적 원인, 재발 조건
4. **개선방향**
   - 최소 변경안, 재발 방지안, 적용·금지 조건, 검증 방법
5. **절감 효과**
   - 기준 작업시간, 개선 후 예상시간, 예상 절감시간, 반복 수고 감소율
   - 산정 근거가 없으면 숫자를 만들지 않고 `NOT_ESTIMATED`로 표시
6. **승인 결론**
   - `APPROVE_FOR_REVIEW_STAGE`, `HOLD`, `BLOCKED`, `OPERATOR_DECISION_REQUIRED`
7. **조치 결과**
   - 실제 실행한 조치, 실행하지 않은 조치, 검증 결과, 잔여 위험, 다음 승인 주체

## 군집 보고 원칙

- 동일 Intent_DNA·원인·개선방향은 한 군집으로 묶되 원본 항목 ID를 모두 보존한다.
- 보안·권한·개인정보·금전·배포 경계가 다른 항목은 같은 군집으로 합치지 않는다.
- 대표 표본만 검증하고 전체를 승인하는 추정 승인은 금지한다.
- 시간 절감 추정치는 범위와 산정식을 함께 기록한다.
- 원 프로젝트의 비밀, 개인정보, 운영 데이터는 복사하지 않고 일반화된 증거 참조만 남긴다.

## 권장 요약 형식

| 구분 | 내용 |
|---|---|
| Intent_DNA | 목표·제약·금지·성공조건 |
| 분석 | 대상 수, 군집 수, 영향 |
| 원인 | 직접·구조 원인 |
| 개선방향 | 최소 변경, 재발 방지, 검증 |
| 절감 효과 | 시간·반복 수고·산정 근거 |
| 결론 | 승인/보류/차단/운영자 결정 |
| 조치 | 실행·검증·잔여 위험 |

## 실패폐쇄 조건

Intent_DNA 누락, 원본 항목 추적 불가, 증거 해시 불일치, 승인 권한 불명, 고위험 항목 혼합,
운영자료 오염, 테스트 실패 또는 절감치 근거 부재를 성공처럼 표시한 경우 보고서를 거부한다.
