# ARKAON 원천세·급여공제 문서학습 패턴 (Pattern Foundry #050)

조회일: 2026-09-22  
상태: ETHERNIAN_REVIEW_REQUIRED / PROPOSE_ONLY

## 목적

사업자가 제공한 급여정보로 원천징수이행상황신고서와 내부 합계표를 준비하는 과정을
재사용 가능한 검토 워크플로로 추상화한다. 실제 주민등록번호, 급여 원장, 인증서,
신고 파일 및 납세자별 산출물은 학습기억에 저장하지 않는다.

## 표준 흐름

```text
요청 범위 확인
→ 최신 공식 서식·시행일 확인
→ 지급월/귀속월 분리
→ 과세·비과세 급여 판정
→ 공제대상 가족·자녀 조건 확인
→ 최신 간이세액표로 소득세 계산
→ 지방소득세 별도 계산
→ 대표자·연령·가입상태별 사회보험 적용 판정
→ 월별 신고서 생성
→ 실제 지급분과 예정분 분리
→ 합계표·급여공제표 생성
→ 산술·렌더링·민감정보 검증
→ 사용자 검토
→ 홈택스·위택스 수동 제출
```

## 불변 규칙

1. 월별 신고 사업자의 여러 지급월을 하나의 신고서로 합쳐 제출하지 않는다.
2. 귀속연월과 지급연월을 같은 값으로 추정하지 않는다.
3. 총지급액과 과세급여를 구분하고 비과세 항목은 법정 요건 충족 여부를 표시한다.
4. 대표자라는 이유만으로 국민연금·건강보험 적용을 단정하지 않는다. 연령, 자격취득일,
   임의계속가입 및 공단 고지서를 확인한다.
5. 지방소득세는 원천징수이행상황신고서의 국세 납부액과 분리한다.
6. 지급 전 금액은 예정표로 표시하고 신고실적으로 합산하지 않는다.
7. 신고기한이 지난 기간은 기한후 신고와 가산세 검토 필요성을 표시하되 제출일 없이
   가산세를 임의 확정하지 않는다.
8. 계산표, 신고서, 합계표의 총지급액·소득세·지방소득세 합계를 상호 대조한다.
9. 주민등록번호 원문, 인증서, 계좌, 연락처 등은 학습자산과 공개 저장소에 넣지 않는다.
10. ARKAON은 초안·검증·설명까지만 수행하며 로그인, 서명, 제출, 납부를 자동 실행하지 않는다.

## 입력 확인표

- 사업자 상호·사업자등록번호·사업장 소재지
- 대표자 또는 근로자 구분
- 입사일, 귀속기간, 실제 지급일
- 월 급여와 입사월 일할계산 방식
- 비과세 항목별 금액과 요건
- 본인 포함 공제대상 가족 수와 해당 자녀 수
- 원천징수 비율 80%·100%·120%
- 사회보험 자격 및 실제 공단 고지액
- 기존 신고·납부 이력
- 실제 제출 예정일

## 검증 증거

- 국세청 또는 국가법령정보센터의 최신 서식 게시일·시행일
- 국세청 간이세액표 시행일과 입력조건
- 보건복지부·국민연금공단의 해당 연도 요율·상하한
- 월별 계산 입력과 결과의 재현 가능한 산식
- PDF 텍스트 추출 및 화면 렌더링 검사
- 개인정보 비포함 검사

공식 URL은 실행 시점에 다시 조회한다. 세율과 서식 버전을 정적 기억값으로 신뢰하지 않는다.

## 학습기억 허용 범위

허용: 추상 순서, 검증 체크리스트, 공식 출처 종류, 실패사례, 합계 대조 규칙.  
금지: 실제 개인식별정보, 실제 급여대장, 인증정보, 납부수단, 제출 세션, 회사별 비공개 원본.

## 상태와 승인

이 패턴은 `ETHERNIAN_REVIEW_REQUIRED` 후보이다. 운영자가 승인해도 자동 신고 권한은
생기지 않는다. 운영 적용은 별도 권한·감사·제출 승인 게이트를 필요로 한다.
