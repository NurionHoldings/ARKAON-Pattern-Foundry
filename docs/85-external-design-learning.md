# 외부 디자인 조사에서 구현 개선까지

## 지금 가능한 것과 아직 아닌 것

기존 cross_platform_learning은 route/funnel 공통 신호를 주로 다룬다. 디자인 편집 성능을
측정한 결과와 동일하지 않다. research_watch는 기본적으로 LOCAL_MANIFEST 변경 감지이며
모델 재학습/웹 자율 순회/코드 자동 배포가 아니다. 본 변경은 명함·로고 분야의 공개 문서
조사에서 기존 우편함으로 구체적인 구현 후보를 만드는 실행 경로를 추가한다.

`PYTHONPATH=src python tools/design_learning.py --baseline <40자리 커밋>`

기본은 읽기/수집과 보고만 수행한다. `--write`는 state/design-learning에 관찰 보고를,
inbox/eternian-review에 구현 후보를 저장한다. 기존 ArkaonMailbox.sync_from_inbox가
소비할 수 있다. 같은 기능·출처·기준 커밋·시험계획은 같은 packet_id로 중복을 막고 기존
검토 기록을 덮어쓰지 않는다. 한 출처의 접속 실패로 다른 출처 처리를 중단하지 않는다.
기존 운영 PC/15초 relay에서 이 명령의 정기 실행을 연결한 것은 아니다.

## 첫 학습 대상과 구체적인 작업 지시

2026-10-24 미리캔버스 공식 공개 자료를 에테르니언이 조사했다.
- https://www.miricanvas.com/en/features/logo-maker
  로고 생성 이후 요소 크기·위치·간격·정렬 수정 기능을 설명한다.
- https://help.miricanvas.com/hc/ko/articles/4411396671769
  브랜드 키트에 로고·색상·글꼴을 묶어 관리하는 방식을 설명한다.

이는 공식 문서의 기능 주장이다. 로그인한 편집기 실행/성능/사용성 측정 증거가 아니다.
키워드 신호 검출은 조사 후보 분류이며 외부 콘텐츠의 지시를 실행하지 않는다.
전체 템플릿·이미지·소스·브랜드 표현을 제품 자산으로 가져오지 않는다. 직접 재사용 요청은
기존 권리 근거/동의 검토 범위로 분리한다.

1. 요소 편집: 독립 SVG 요소 모델에서 심벌 크기·문자 간격·정렬을 조절하고 10회 undo/redo
   후 동일 상태를 재현한다. 60자 한글 상호의 잘림/겹침을 0건으로 만든다.
2. 브랜드 키트: 사용자 자산과 허용된 글꼴을 버전으로 묶어 로고·명함·홈페이지에 같은 설정을
   적용한다. 이전 버전 복원과 교차 사용자 접근 차단을 시험한다.
3. 우리 기준선은 측정 전 MEASUREMENT_REQUIRED다. 외부 설명을 읽었다고 우리 기능이
   없거나 타사가 우월하다고 자동 판정하지 않는다. #121은 현재 제작 UI의 별도 개발 라인이다.
4. 태양광/카페/개인 디자이너의 같은 brief로 전후 커밋·결과물 해시, 360/390/768/1440px
   화면, 완주 단계·시간·오류를 기록한다. 새 기능의 회귀시험을 포함한다.
5. 아르카온은 승인된 구현 범위에서 sandbox 변경과 1차 시험을 담당한다. 에테르니언은
   독립 비교/감사를 담당한다. 범위 승인과 운영 반영 승인은 별개다.

관찰 → 구현 후보까지 자동화했다. 실제 baseline 측정/개발 runner 연결/브라우저 화면 수집/
독립 감사/승인 후 브랜드 자산 활성화/운영 worker 정기 실행은 미완료다.
모든 출력은 CANDIDATE_EVIDENCE_ONLY이며 improvement_accepted=false다.
단일 서비스 사례도 조사·구현 후보로 사용할 수 있으나 일반적 우수성/법적 적합성/전례 없는
독창성을 자동 인정하지 않는다. 위 성과가 검증된 후만 승인된 자산으로 승격한다.

## 내부 추적과 사용자 화면의 출처 표시 구분

공개 서비스의 일반적인 편집 원리/흐름을 참고해 자체 코드로 구현한 기능에는 조사 대상
서비스명을 기능 화면에 자동 표기하지 않는다. source_url/digest/관찰 시각은 내부 검토용이며
제품 결과물 HTML/SVG에 자동 삽입하지 않는다. 조사 기록은 학습 평가 근거로 보존한다.
외부 디자인/이미지/템플릿 자체를 예시로 사용하면 허용 범위·출처표시 조건을 별도 확인한다.
외부 코드·폰트·라이브러리를 실제 채택하면 해당 라이선스 고지 조건을 따른다.
출처표시 유무와 사용 허가 유무는 별개이며, 표시만으로 사용 권한이 생기는 것으로 처리하지 않는다.
