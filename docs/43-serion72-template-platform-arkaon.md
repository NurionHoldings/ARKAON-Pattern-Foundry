# 43. SERI ON 72 템플릿·플랫폼 ARKAON 준비팩

## 1. 목적

SERI ON 72에서 검증한 가족 제안형 사업계획서 구조를 ARKAON이 재사용 가능한 프로젝트 지식으로 학습한다. 현재 단계는 템플릿 제작과 플랫폼 전환 준비이며, 운영 자동화·외부 공개·자산 승격은 수행하지 않는다.

## 2. 상태와 경계

- 상태: `ETHERNIAN_REVIEW_REQUIRED`
- 런타임: `INACTIVE`
- 공개 Pattern 후보 30개: 변경하지 않음
- Intent_DNA: 기존 원장을 변경하지 않고 프로젝트 전용 입력으로 격리
- 외부 쓰기, 결제, 회원, 개인정보, 자동 배포: 비활성
- 사용자 화면: 아르카온 학습용어와 개발용어를 노출하지 않음
- 승인 주체: 에테르니언 최종 감사 후 사용자 승인

## 3. SERI ON 72에서 학습할 핵심

### 3.1 제안서 구조

1. 제안 대상과 목적을 한 문장으로 잠근다.
2. 핵심 메시지를 첫 화면에 배치한다.
3. 사업 아이디어를 독립 축으로 유지한다.
4. 각 축에 목표, 설계, 재원, 검증항목, 결정사항을 동일한 순서로 채운다.
5. 포트폴리오 전체의 우선순위, 거버넌스, 재무 시나리오, 위험, 90일 실행계획을 연결한다.
6. 대상자가 읽는 화면에서는 내부 학습·감사 용어를 숨긴다.

### 3.2 이미지 선택

선택 우선순위는 직접 활동사진 → 동일 업종 실제 이미지 → 연관 업종 이미지다.

이미지는 사업의 고객·공간·행동·결과 중 하나를 설명해야 한다. 설명하지 못하는 장식용 이미지는 제외한다. 외부 이미지가 실패하면 브랜드 색상의 대체 배경과 설명을 유지한다.

### 3.3 애니메이션

- 주 애니메이션은 화면당 하나를 원칙으로 한다.
- 브랜드 마크에는 호흡·궤도·빛 이동을 절제해 사용한다.
- 상세 이미지는 항목이 열릴 때 1회만 확대·페이드한다.
- `transform`과 `opacity` 중심으로 구성한다.
- `prefers-reduced-motion`에서는 반복·이동 효과를 정지한다.
- 모바일에서는 지속시간, 레이어, 동시 효과 수를 축소한다.

### 3.4 반응형

- 1440px 이상: 넓은 여백과 이미지 깊이를 확장한다.
- 1024px 이하: 3열을 2열로 축소하고 메뉴를 단순화한다.
- 780px 이하: 모든 핵심 흐름을 1열로 전환한다.
- 420px 이하: 서명, 필터, 상세 카드와 긴 제목의 줄바꿈을 우선한다.
- 가로 스크롤, 터치 지연, 이미지 잘림, 200% 텍스트 확대를 검사한다.

## 4. 플랫폼 전환 단계

### 단계 A — 읽기형 제안서

- 정적 템플릿
- 사업축 펼침·필터
- 이미지와 애니메이션
- 인쇄·PDF
- 개발용어 비노출

### 단계 B — 편집형 계획서

- 승인된 사용자만 사업축 추가·수정
- 이미지 후보 추천과 실패 감지
- 수치·가정·출처 구분
- 변경이력과 검토 상태
- 미리보기와 승인본 분리

### 단계 C — 협업형 제안 플랫폼

- 역할별 검토
- 댓글·승인·반려
- 재무 시나리오 버전
- 증거자료 연결
- 외부 공유 범위 설정

### 단계 D — 사업 운영 연결

- 승인된 사업만 실행 프로젝트로 전환
- 책임자·일정·예산·성과지표 연결
- 정산·계약·개인정보 기능은 별도 보안 게이트 통과 후 연동
- Pattern Foundry는 설계자산과 학습결과만 제공하고 운영 시스템의 SoT가 되지 않는다.

## 5. ARKAON 생성 절차

```
CAPTURE_INTENT
→ CLASSIFY_AUDIENCE
→ LOCK_MESSAGE
→ SPLIT_BUSINESS_AXES
→ COMPLETE_STANDARD_FIELDS
→ SELECT_EVIDENCE_MEDIA
→ APPLY_MOTION_BUDGET
→ RESPONSIVE_AUDIT
→ HIDE_INTERNAL_TERMS
→ ETHERNIAN_REVIEW
→ USER_APPROVAL
→ PUBLISH_OR_REVISE
```

## 6. 품질 게이트

- 제안 대상과 메시지가 첫 화면에서 이해되는가
- 각 사업축의 결정사항이 명확한가
- 수치가 확정값과 가정값으로 구분되는가
- 이미지가 해당 사업을 실제로 설명하는가
- 이미지 실패 시 내용이 유지되는가
- 모바일에서 가로 밀림과 잘림이 없는가
- 동작을 제거해도 의미와 기능이 유지되는가
- 내부 개발·학습 용어가 제안 화면에 노출되지 않는가
- 승인 전 운영 반영이나 공용 자산 승격이 없는가

## 7. 재사용 출력물

ARKAON은 향후 동일 유형 요청에서 다음 산출물을 만들 수 있도록 준비한다.

- 제안 대상별 사업계획 템플릿
- 사업축 데이터 모델
- 이미지 브리프와 선택 근거
- 애니메이션 예산표
- 모바일·PC 검토표
- 재무 시나리오 틀
- 90일 실행계획
- 에테르니언 감사 요청서

## 8. 활성화 조건

다음 조건을 모두 만족할 때만 편집형 또는 협업형 플랫폼 구현을 시작한다.

1. 에테르니언 검토 완료
2. 사용자 승인
3. 데이터 저장 범위 확정
4. 인증·역할·공개범위 결정
5. 개인정보·계약·결제 연동 여부 결정
6. 테스트와 롤백 계획 확정

현재 이 문서는 준비 자산이며 운영 승인 또는 공용 Pattern 승격을 의미하지 않는다.
