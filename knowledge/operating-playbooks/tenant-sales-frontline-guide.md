# 입점업체 매출·수수료 현장 업무 가이드

이 가이드는 판매·세무·전산 경험이 없는 운영 담당자가 업무 순서를 익히도록 돕는 제안형 지식이다. 공식 실행 예제와 화면별 세부 절차는 [addon-polo 실무자 업무 매뉴얼](https://github.com/NurionHoldings/addon-polo/pull/1/files/docs/%EC%8B%A4%EB%AC%B4%EC%9E%90-%EC%97%85%EB%AC%B4%EB%A7%A4%EB%89%B4%EC%96%BC.md)을 참조한다.

## 하루 업무

1. POS·온라인몰·라이브방송 채널별 판매 자료를 받는다.
2. 채널과 기간, 업체 이름을 확인한다.
3. CSV 업로드 전 업체 매출 합계와 환불·취소가 포함됐는지 확인한다. 거래액은 고객이 할인 뒤 실제 낸 금액이다.
4. 매출은 `sale`, 환불은 `refund`, 취소는 `cancel`로 기록한다. 환불이나 취소는 원래 매출을 지우지 않고 새 음수 사건으로 남긴다.
5. PG 정산 예정액을 통장에 실제 입금된 금액과 정산 참조번호별로 맞춘다. 차액은 자료로 조사하고 담당자가 확인할 때까지 그대로 표시한다.

## 월 마감

1. 모든 판매 채널의 월 자료가 들어왔는지 확인한다.
2. 매출·환불 합계를 POS/채널 원본 자료와 비교한다.
3. 확인필요 입금 내역을 검토한다.
4. 계약서의 수수료율과 과세 구분에 맞는지 확인한 다음 업체별 월 명세를 만든다.
5. 명세는 한 번 생성되면 그 시점의 확정본이다. 생성 전에 자료를 확인하고, 이후 정정은 관리자와 회계 담당자에게 알린다.
6. 수수료를 실제 받은 뒤에만 수납 완료로 표시한다. 판매대금 입금 대사와 수수료 납부 기록은 서로 다른 업무다.

## 쉬운 판단 규칙

- 같은 파일을 또 올리라는 요청이 나오면 먼저 이미 들어갔는지 검색한다. 같은 자료를 다른 이벤트 ID로 다시 올려 중복시키지 않는다.
- 이미 등록한 원본 거래를 고치거나 지우지 않는다. 원본 증빙을 보관하고 관리자에게 정정 방법을 확인한다.
- 차액이 생겼다고 예상액이나 입금액을 맞춰 바꾸지 않는다. 카드/PG 자료와 통장 기록을 다시 확인한다.
- 수수료 산식, 상품세액, 환불을 다음 달로 넘기는 방법은 계약과 회계 처리를 확인한다.
- 소프트웨어는 입금 차이를 알려줄 수 있지만 은행 송금이나 업체 자금 보관을 하지 않는다.
- 자동 채널 연동이 없다면 권한을 받아 공식 자료를 내려받아 CSV로 올린다. 계정 비밀번호를 수집하거나 비공식 화면을 자동 수집하지 않는다.

## 상태의 뜻

| 화면 상태 | 뜻 |
|---|---|
| 대사완료 | 입력한 예정 입금액과 통장 실입금액이 같다 |
| 확인필요 | 예정액과 실제 입금액이 다르다. 원본 자료를 확인해야 한다 |
| 발행 | 월 수수료 명세를 만들었으나 납부 완료를 표시하지 않았다 |
| 수납완료 | 업체 수수료 납부를 담당자가 확인해 표시했다 |

## 제한

현재 운영 앱은 수동 입력과 CSV 자료 처리를 지원한다. POS/PG/은행 API 자동 연동은 제공되지 않는다. 정산 참조번호는 채널마다 한 번만 등록할 수 있어, 업로드 전에 값과 금액을 확인한다. 이 가이드는 Pass-0, propose-only 학습 자료이며 locked Intent_DNA를 자동 변경하지 않는다.
