결과물 확인과 운영 준비

먼저 아르카온이 현재 구현한 제작물과 미리보기를 확인합니다. 운영·배포를 원할 때만 다음 개발 및 검증 단계를 살펴보세요.

아르카온이 한 단계씩 안내합니다. 아래 확인 버튼은 사용자가 화면에서 직접 확인했다는 기록이며, Railway 상태를 자동 검증하거나 서비스를 생성하지 않습니다.

배포 허용 상태를 확인하는 중…

지금 확인할 수 있는 결과물

현재 구현된 제작 화면에서 실제 시안과 수정·미리보기 흐름을 확인하세요. 기능별 완성 범위는 해당 화면의 안내를 따릅니다.

  • SVG 로고와 애니메이션 시안
  • 명함 앞·뒷면 시안
  • 랜딩페이지 시안
  • 플랫폼 홈·상세 화면 시안

현재 결과물 확인은 운영 중인 서비스 완성을 뜻하지 않습니다. 다음 개발 단계: GitHub 저장·서비스별 계정·DB·API 설계, Railway 실환경 검증, Netlify 미리보기와 공개 배포 연결.

운영을 원할 때 알아두세요

현재 연결은 안내 전용입니다. 비밀번호·OAuth 비밀값·데이터베이스 주소를 이 화면에 입력하지 마세요. 실제 생성은 Railway의 공식 화면에서 사용자가 직접 누릅니다. 최종 활성화는 별도 검증과 승인 후 가능합니다.

3 / 8 · 데이터베이스

PostgreSQL 만들기

Railway 프로젝트에서 Add → Database → PostgreSQL을 선택합니다. Postgres의 postgres-volume은 데이터베이스 전용입니다. Postgres 카드에 Online이 보이는지 확인하세요.

공식 설명 ↗

4 / 8 · 앱 저장 공간

앱에 별도 볼륨 연결

앱 서비스 ARKAON-Pattern-Foundry에 별도 Volume을 추가하고 Mount path를 /data로 지정합니다. 앱 카드가 아직 생성 대기라면 이 단계에서 멈춥니다. Postgres 카드에 앱 변수를 넣지 마세요.

볼륨 설명 ↗

5 / 8 · 앱 설정

앱 서비스 변수 연결

앱 Variables에서 DATABASE_URL을 ${{Postgres.DATABASE_URL}} 참조로 설정하고, APF_ENV=production, APF_RUNTIME_ROOT=/data/runtime, APF_FOUNDRY_ROOT=/data/foundry를 넣습니다. 서비스 이름이 다르면 참조 이름도 맞춥니다.

변수 설명 ↗

6 / 8 · 관리자 로그인

HTTPS 주소와 GitHub OAuth 연결

앱 도메인을 정한 뒤 GitHub OAuth App의 콜백을 https://내-도메인/console/auth/callback으로 설정합니다. 앱 Variables에 Client ID·Secret, 허용할 GitHub 숫자 ID, Tenant UUID, HTTPS 원점과 세션 비밀값을 입력합니다. 비밀값은 이 화면에 붙여 넣지 않습니다.

DB 초기화와 재시작 검증

마이그레이션 적용, Tenant 생성, 앱 볼륨의 재시작 후 보존, 백업 복구, 관리자 로그인과 비관리자 차단, 공개 HTTPS URL 관찰을 검증합니다. /health 성공만으로 기능 준비를 판정하지 않습니다.
